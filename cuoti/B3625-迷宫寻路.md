# B3625 迷宫寻路

**标签**：BFS、搜索、语法坑

**记录日期**：2026-09-23

## 题目来源与链接

洛谷 B3625 迷宫寻路：https://www.luogu.com.cn/problem/B3625

## 题目大意

给一个 n×m 的矩阵迷宫，`.` 是空地，`#` 是障碍。机器猫从左上角 (1,1) 出发，每步只能上下左右走到相邻的空地，问它能不能走到右下角 (n,m)。能就输出 `Yes`，不能就输出 `No`。

## 我的错误代码

提交结果：**TLE**，只拿到部分分。

```cpp
#include<bits/stdc++.h>
using namespace std;
char grid[101][101];
bool vis[101][101];
int n,m=0;
int dx[4]={-1,1,0,0};
int dy[4]={0,0,-1,1};
struct node{ int x; int y; };
int main(){
    int flag=0;
    cin>>n>>m;
    for(int i=1;i<=n;i++)
        for(int j=1;j<=m;j++)
            cin>>grid[i][j];
    queue<node> q;
    q.push({1,1});
    vis[1][1]=true;
    while(!q.empty()){
        node pre=q.front();
        q.pop();
        if(pre.x==n&&pre.y==m){
            flag=1;
            printf("Yes");
            break;
        }
        for(int i=0;i<4;i++){
            int sx=pre.x+dx[i];
            int sy=pre.y+dy[i];
            if(sx>=1&&sx<=n&&sy>=1&&sy<=m&&grid[sx][sy]=='.'&&!vis[sx][sy])
                vis[sx][sy]=true;
                q.push({sx,sy});
        }
    }
    if(!flag)
        printf("No");
    return 0;
}
```

## 错误原因分析

问题就在这三行：

```cpp
if(sx>=1&&sx<=n&&sy>=1&&sy<=m&&grid[sx][sy]=='.'&&!vis[sx][sy])
    vis[sx][sy]=true;
    q.push({sx,sy});
```

`if` 后面没加花括号，它只管紧跟着的那一条语句，也就是只有 `vis[sx][sy]=true;` 受条件约束。缩进在 C++ 里不表示从属关系，`q.push({sx,sy});` 实际上已经跳出了 `if` —— 不管坐标越没越界、是不是墙、访问过没访问过，每轮循环都照样入队。

这一行漏出去，同时毁掉了两样东西。

**一是正确性：搜索会穿墙。** 墙和越界坐标照样进队，而出队时的终点判断 `pre.x==n&&pre.y==m` 对这些"非法来路"的点一样成立。把这份错误代码照搬成 Python 实测：3×3 的图里起点四面被墙堵死（正确答案 `No`），它弹出 181 次之后照样输出 `Yes`；4×4 终点被封死的图同样输出 `Yes`。所以在小数据上它不是"没跑完"，而是**跑完了但答错了**。

**二是效率：队列彻底失控。** `vis` 完全失去了"防止重复入队"的作用，每弹出 1 个点就无条件压进 4 个点，队列每轮净增 3 个，而且毫无去重，第 d 层有 4^d 个点。终点在第 (n-1)+(m-1) 层：8×8 的图弹出 200 万次都还没结束，100×100 要走到第 198 层，4^198 这个量级根本跑不到。

两者合起来正好解释了提交结果：**小测试点秒出 `Yes`**（那个点答案正好是 `Yes` 就白捡一分，答案是 `No` 就是错的），**大测试点队列爆炸 TLE**，于是最终显示 TLE + 部分分。

## 正确代码

"标记已访问"和"入队"必须是一对，一起放进 `if` 的花括号里：

```cpp
#include<bits/stdc++.h>
using namespace std;
char grid[101][101];
bool vis[101][101];
int n,m=0;
int dx[4]={-1,1,0,0};
int dy[4]={0,0,-1,1};
struct node{ int x; int y; };
int main(){
    int flag=0;
    cin>>n>>m;
    for(int i=1;i<=n;i++)
        for(int j=1;j<=m;j++)
            cin>>grid[i][j];
    queue<node> q;
    q.push({1,1});
    vis[1][1]=true;
    while(!q.empty()){
        node pre=q.front();
        q.pop();
        if(pre.x==n&&pre.y==m){
            flag=1;
            printf("Yes");
            break;
        }
        for(int i=0;i<4;i++){
            int sx=pre.x+dx[i];
            int sy=pre.y+dy[i];
            if(sx>=1&&sx<=n&&sy>=1&&sy<=m&&grid[sx][sy]=='.'&&!vis[sx][sy]){
                vis[sx][sy]=true;   // 标记和入队必须一起被 if 管住
                q.push({sx,sy});
            }
        }
    }
    if(!flag)
        printf("No");
    return 0;
}
```

## 关键收获

`if` / `for` 后面只要有多条语句要一起生效，就必须加花括号，缩进骗不了编译器；BFS 里"打标记"和"入队"是不可拆的一对，拆开之后小图穿墙输出错误的 `Yes`、大图队列爆炸 TLE——同一个花括号，两种症状。
