# B3625 迷宫寻路

**标签**：BFS、搜索、语法坑

**记录日期**：2026-09-23

## 题目来源与链接

洛谷 B3625 迷宫寻路：https://www.luogu.com.cn/problem/B3625

## 题目大意

给一个 n×m 的矩阵迷宫，`.` 是空地，`#` 是障碍。机器猫从左上角 (1,1) 出发，每步只能上下左右走到相邻的空地，问它能不能走到右下角 (n,m)。能就输出 `Yes`，不能就输出 `No`。

## 我的错误代码

提交结果：**TLE**，只拿到部分分。

```cpp
#include<bits/stdc++.h>
using namespace std;
char grid[101][101];
bool vis[101][101];
int n,m=0;
int dx[4]={-1,1,0,0};
int dy[4]={0,0,-1,1};
struct node{ int x; int y; };
int main(){
    int flag=0;
    cin>>n>>m;
    for(int i=1;i<=n;i++)
        for(int j=1;j<=m;j++)
            cin>>grid[i][j];
    queue<node> q;
    q.push({1,1});
    vis[1][1]=true;
    while(!q.empty()){
        node pre=q.front();
        q.pop();
        if(pre.x==n&&pre.y==m){
            flag=1;
            printf("Yes");
            break;
        }
        for(int i=0;i<4;i++){
            int sx=pre.x+dx[i];
            int sy=pre.y+dy[i];
            if(sx>=1&&sx<=n&&sy>=1&&sy<=m&&grid[sx][sy]=='.'&&!vis[sx][sy])
                vis[sx][sy]=true;
                q.push({sx,sy});
        }
    }
    if(!flag)
        printf("No");
    return 0;
}
```

## 错误原因分析

问题就在这三行：

```cpp
if(sx>=1&&sx<=n&&sy>=1&&sy<=m&&grid[sx][sy]=='.'&&!vis[sx][sy])
    vis[sx][sy]=true;
    q.push({sx,sy});
```

`if` 语句缺少花括号，导致 `q.push({sx,sy})` 脱离了判断条件，变成每次循环都无条件执行——不管坐标越不越界、是不是墙、有没有访问过都会入队。缩进在 C++ 里不表示从属关系，`if` 只管紧跟着它的那一条 `vis[sx][sy]=true;`。

**这一个 bug 会因为数据规模不同，呈现出两种不同的表现：**

- **小数据 → WA**：非法坐标（越界 / 穿墙）被提前推入队列，可能让终点判断 `pre.x==n&&pre.y==m` 在还没真正走到终点时就提前命中，输出错误的 `Yes` —— 答案错误，但程序正常跑完。实测：3×3 的图里起点四面被墙堵死、正确答案是 `No`，它弹出 181 次就输出了 `Yes`；4×4 终点被封死的图同样输出 `Yes`。
- **大数据 → TLE**：队列被大量非法 / 重复坐标不断撑爆 —— 每弹出 1 个点就无条件压进 4 个，没有任何去重，第 d 层有 4^d 个点，弹出次数指数级增长，程序来不及跑完就被判超时。实测：8×8 的图弹出 200 万次都还没结束；终点在第 (n-1)+(m-1) 层，100×100 要走到第 198 层，4^198 这个量级根本跑不到。

**两种现象根源完全相同：都是那对缺失的花括号。** 补上花括号、让 `vis` 赋值和 `q.push` 都被 `if` 条件正确约束之后，两种问题会同时消失。

这次提交最终显示 TLE + 部分分，就是这两种表现落在不同测试点上的结果。

## 正确代码

"标记已访问"和"入队"必须是一对，一起放进 `if` 的花括号里：

```cpp
#include<bits/stdc++.h>
using namespace std;
char grid[101][101];
bool vis[101][101];
int n,m=0;
int dx[4]={-1,1,0,0};
int dy[4]={0,0,-1,1};
struct node{ int x; int y; };
int main(){
    int flag=0;
    cin>>n>>m;
    for(int i=1;i<=n;i++)
        for(int j=1;j<=m;j++)
            cin>>grid[i][j];
    queue<node> q;
    q.push({1,1});
    vis[1][1]=true;
    while(!q.empty()){
        node pre=q.front();
        q.pop();
        if(pre.x==n&&pre.y==m){
            flag=1;
            printf("Yes");
            break;
        }
        for(int i=0;i<4;i++){
            int sx=pre.x+dx[i];
            int sy=pre.y+dy[i];
            if(sx>=1&&sx<=n&&sy>=1&&sy<=m&&grid[sx][sy]=='.'&&!vis[sx][sy]){
                vis[sx][sy]=true;   // 标记和入队必须一起被 if 管住
                q.push({sx,sy});
            }
        }
    }
    if(!flag)
        printf("No");
    return 0;
}
```

## 关键收获

`if` / `for` 后面只要有多条语句要一起生效，就必须加花括号，缩进骗不了编译器；BFS 里"打标记"和"入队"是不可拆的一对，拆开之后小图穿墙输出错误的 `Yes`、大图队列爆炸 TLE——同一个花括号，两种症状。
